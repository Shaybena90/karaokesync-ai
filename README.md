# KaraokeSync AI 🎤

מעלים שיר (MP3 / WAV / M4A) ומקבלים כתוביות קריוקי שמסונכרנות לכל מילה — בעברית (RTL), באנגלית ובשפות נוספות.

| שלב | מצב |
|---|---|
| 1. פרויקט React + מסך בית רספונסיבי + PWA | ✅ |
| 2. Supabase: הרשמה, כניסה, שחזור סיסמה, Google (אופציונלי) | ✅ |

| 6. נגן קריוקי מלא | 🟡 יש תצוגה מקדימה מסונכרנת בסיסית; הנגן המלא בשלב הבא |

| תיקייה | מה יש בה |

### למה תור ב-PostgreSQL?
העבודות נשמרות בטבלה `processing_jobs` ב-Supabase:
- **אין עיבוד כפול:** Worker לוקח עבודה עם `FOR UPDATE SKIP LOCKED` — שני Workers לעולם לא יקבלו את אותה עבודה.
- **התאוששות מקריסה:** כל עבודה "מושכרת" ל-Worker לזמן מוגבל ומתחדשת בדופק (heartbeat). אם ה-Worker קורס — העבודה חוזרת לתור אוטומטית.
- **ניסיונות חוזרים:** עד 3 ניסיונות עם המתנה הולכת וגדלה.
- **אין עבודות כפולות:** אינדקס ייחודי במסד הנתונים מונע שתי עבודות פעילות לאותו קובץ (גם בלחיצה כפולה).
- אין צורך בשירות נוסף (Redis וכו'), וזה עובד גם בתוכנית החינמית.

## 🖥️ התקנה והפעלה במחשב Windows (צעד אחר צעד)

### שלב א׳ — להתקין תוכנות (פעם אחת)

1. **Node.js** — הורידו את גרסת LTS מ-https://nodejs.org והתקינו (Next, Next, Finish).
2. **Python 3.12** — מ-https://www.python.org/downloads/ . במסך הראשון של ההתקנה **סמנו ✅ "Add python.exe to PATH"**.
3. **FFmpeg** — פתחו את "Command Prompt" (חפשו `cmd` בתפריט התחל) והקלידו:
   ```
   winget install Gyan.FFmpeg
   ```
   אחרי ההתקנה **סגרו ופתחו מחדש** את חלון ה-cmd.
4. בדיקה — בחלון cmd חדש הקלידו את שלוש הפקודות; כל אחת צריכה להדפיס מספר גרסה:
   ```
   node --version
   py --version
   ffmpeg -version
   ```

### שלב ב׳ — ליצור פרויקט Supabase (חינם)

1. היכנסו ל-https://supabase.com ← **Start your project** ← התחברו ← **New project**.
   בחרו שם, סיסמה למסד הנתונים (שמרו אותה), ואזור קרוב (למשל Frankfurt).
2. כשהפרויקט מוכן: בתפריט הצד ← **SQL Editor** ← **New query**.
   פתחו את הקובץ `supabase/migrations/20261028000001_init.sql` (בפנקס רשימות), העתיקו **את כל התוכן**, הדביקו ולחצו **Run**.
   אמורה להופיע הודעה `Success`.
3. **Authentication ← URL Configuration**:
   - Site URL: ‏`http://localhost:5173`
   - Redirect URLs: הוסיפו ‏`http://localhost:5173/**`
4. **Project Settings ← API** (או **API Keys**) — כאן נמצאים המפתחות לשלב הבא.

### שלב ג׳ — קובץ ההגדרות ‎.env

1. בתיקייה הראשית של הפרויקט, העתיקו את `.env.example` לקובץ חדש בשם `.env`
   (או פשוט הריצו את `scripts\windows\1-install.bat` — הוא יוצר אותו לבד).
2. פתחו את `.env` בפנקס רשימות ומלאו:

| משתנה | מאיפה לוקחים |
|---|---|
| `VITE_SUPABASE_URL` ו-`SUPABASE_URL` | ‏Project URL (אותו ערך בשניהם) |
| `VITE_SUPABASE_ANON_KEY` | המפתח **anon / publishable** (ציבורי — בסדר שיגיע לדפדפן) |
| `SUPABASE_SERVICE_ROLE_KEY` | המפתח **service_role / secret** — **סודי!** לא לשתף, לא להעלות ל-GitHub, לא לשים במשתנה שמתחיל ב-`VITE_` |

> לא המצאתי שום מפתח — הקובץ `.env.example` מגיע ריק בכוונה.

### שלב ד׳ — התקנת חבילות

לחיצה כפולה על **`scripts\windows\1-install.bat`**. זה לוקח כמה דקות.

### שלב ה׳ — הפעלה

פתחו **שני** קבצים בלחיצה כפולה (כל אחד נפתח בחלון משלו — אל תסגרו אותם):

1. `scripts\windows\3-start-api.bat` — שרת ה-API (‏http://localhost:8000)
2. `scripts\windows\2-start-website.bat` — האתר

עכשיו פתחו בדפדפן: **http://localhost:5173** 🎉

הירשמו (תקבלו אימייל אישור מ-Supabase), התחברו והעלו שיר.

### שלב ו׳ — עיבוד AI אמיתי (ה-Worker)

בלי ה-Worker, השיר יעלה, ייבדק ויחכה בתור ("בתור לעיבוד").

1. לחיצה כפולה על `scripts\windows\4-install-ai.bat` (הורדה גדולה — כמה GB, פעם אחת).
2. לחיצה כפולה על `scripts\windows\5-start-worker.bat`.
   בהפעלה הראשונה מודל Whisper יורד אוטומטית (‏small ‏≈ 500MB).
3. העבודה בתור תתחיל לרוץ, והאתר יתעדכן בזמן אמת.

**מהירות:** במחשב רגיל בלי כרטיס מסך, שיר של 4 דקות עם המודל `small` לוקח בערך 2–6 דקות. עם GPU של NVIDIA ‏(`WHISPER_DEVICE=cuda`) — הרבה יותר מהר ואפשר להשתמש ב-`large-v3` המדויק יותר.

### לפתוח מהטלפון באותה רשת Wi-Fi
1. בחלון cmd הקלידו `ipconfig` ומצאו את ה-IPv4 Address (למשל `192.168.1.20`).
2. בקובץ `.env`: ‏`VITE_API_URL=http://192.168.1.20:8000` ו-`CORS_ORIGINS=http://localhost:5173,http://192.168.1.20:5173`.
3. הפעילו את האתר עם `npm run dev -- --host` מתוך התיקייה `web`, ואת ה-API עם `--host 0.0.0.0`.
4. בטלפון: ‏`http://192.168.1.20:5173`. (התקנה כ-PWA דורשת HTTPS — תעבוד אחרי הפריסה.)

## 🌍 סנכרון ועברית — מה חשוב לדעת

- **תמלול וזיהוי שפה:** faster-whisper (Whisper) תומך בעברית, אנגלית ועוד ~‏100 שפות.
- **תזמון מילים:** כרגע נמדד באמצעות יישור ה-cross-attention של Whisper (DTW) — מדידה אמיתית מהאודיו, שעובדת בכל שפה שהמודל מתמלל.
- **WhisperX לא תומך בכל השפות באופן שווה:** Forced Alignment מסוג CTC דורש מודל wav2vec2 שאומן על השפה הספציפית, ועברית אינה בין מודלי ברירת המחדל שלו. לכן הקוד ב-`server/karaokesync/worker/alignment.py` בוחר שיטת יישור **לכל שפה במפורש** במקום להניח תמיכה. בשלב 5 המתקדם יתווסף Aligner מבוסס MMS ‏(torchaudio, מכסה 1,100+ שפות כולל עברית) לשיפור הדיוק, וכן יישור של מילים שהמשתמש מעלה בעצמו.
- **הפרדת שירה (Demucs):** אופציונלית (`ENABLE_VOCAL_SEPARATION=true`). משפרת זיהוי בשירים עם מוזיקה רועשת, אבל איטית מאוד בלי GPU. אם היא נכשלת — העיבוד ממשיך עם המיקס המקורי.
- **הנגן** מסתמך תמיד על זמן הניגון האמיתי של קובץ האודיו (`currentTime`), לא על טיימר נפרד — ולכן קפיצה קדימה/אחורה מעדכנת את הכתוביות מיד.

## 🔒 אבטחה ופרטיות

- **Private Buckets** — קבצי שמע לא נגישים לציבור; ניגון דרך Signed URL קצר תוקף.
- **העלאה ישירה לאחסון:** ה-API מנפיק הרשאת העלאה **חד-פעמית לנתיב אחד בלבד** (`user_id/project_id/...`) — הקובץ לא עובר דרך שרת האתר.
- **בדיקת קובץ אמיתית:** גם בדפדפן וגם בשרת — "Magic bytes" + ‏ffprobe. קובץ שאינו שמע אמיתי, או שהתוכן שלו לא תואם לסיומת — נמחק ונדחה.
- **Row Level Security** על כל הטבלאות: כל משתמש רואה רק את שלו. הדפדפן לא יכול לשנות סטטוסים, ליצור עבודות או לקרוא לפונקציות התור (נבדק אוטומטית ב-`supabase/tests`).
- **מפתח service role** קיים רק בשרת. ה-build של האתר נכשל בכוונה אם משתנה סודי מתחיל ב-`VITE_`.
- **מכסות:** העלאות ליום, עבודות פעילות במקביל, ניסיונות חוזרים, והגבלת קצב בקשות.
- **מחיקה:** המשתמש יכול למחוק פרויקט + הקבצים. קבצים ישנים נמחקים אוטומטית אחרי `AUDIO_RETENTION_DAYS` (ברירת מחדל 30 יום), והעלאות שלא הושלמו — אחרי 24 שעות. קבצי עבודה זמניים של ה-Worker נמחקים תמיד בסיום.
- **לוגים:** טוקנים, מפתחות ו-Signed URLs מסוננים אוטומטית; תוכן אודיו לא נרשם.

## 🚀 פריסה (הוראות — עדיין לא בוצעה)

> ⚠️ לא אבצע פריסה לשירותים בתשלום בלי אישור שלך.

**1. האתר ב-Vercel**
1. Vercel ← Add New Project ← ייבוא ה-repository מ-GitHub.
2. **Root Directory:** ‏`web`.
3. Environment Variables: ‏`VITE_SUPABASE_URL`, ‏`VITE_SUPABASE_ANON_KEY`, ‏`VITE_API_URL` (כתובת ה-API בענן), ‏`VITE_ENABLE_GOOGLE_AUTH`. **לא** להוסיף את מפתח ה-service role.
4. ב-Supabase ← Authentication ← URL Configuration: הוסיפו את כתובת האתר (למשל `https://karaokesync.vercel.app` ו-`https://karaokesync.vercel.app/**`).

**2. ה-API וה-Worker** (כל שרת שמריץ Docker)
```
cd server
docker build -t karaokesync-server .
docker run -p 8000:8000 --env-file ../.env karaokesync-server                                   # API
docker run --env-file ../.env karaokesync-server python -m karaokesync.worker.runner            # Worker
```
- ל-API מספיק שרת קטן. בנו עם `--build-arg INSTALL_AI=false` כדי לקבל image קטן.
- ה-Worker צריך זיכרון (‏4GB+ ל-`small`), ועדיף GPU. אפשר להריץ כמה Workers במקביל — התור מונע כפילויות.
- ב-`.env` של השרת: ‏`APP_ENV=production`, ‏`CORS_ORIGINS=https://<כתובת האתר שלך>`.

**3. Google Login (אופציונלי)**
Supabase ← Authentication ← Providers ← Google: הזינו Client ID ו-Secret מ-Google Cloud Console, ואז `VITE_ENABLE_GOOGLE_AUTH=true`.
