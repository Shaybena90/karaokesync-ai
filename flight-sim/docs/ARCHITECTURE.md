# ארכיטקטורה

```
                    Content/KanafData (JSON, DEM, WAV, fonts)  ← נתונים בלבד, בנפרד מהקוד
                                   │
        ┌──────────────────────────┴───────────────────────────┐
        │ KanafCore (C++ טהור, ללא Unreal; נבדק ב-CMake)        │
        │  Json · Geo(WGS84) · Atmosphere · Terrain/GroundModel │
        │  Catalog · LoadoutValidator · FlightModel · FCS       │
        │  Session · Mission · Radio(Director) · RadioAudio(DSP)│
        │  Autopilot (טייס בדיקה / מצב הדגמה)                   │
        └──────────────────────────┬───────────────────────────┘
                                   │ (אותו קוד בדיוק)
        ┌──────────────────────────┴───────────────────────────┐
        │ KanafSim (מודול משחק Unreal)                          │
        │  GameSubsystem: טעינת נתונים, בחירות, הגדרות שמורות    │
        │  GameMode: תפריט ← האנגר ← טיסה ← סיכום                │
        │  AircraftPawn: קלט, מצלמות, אנימציה, אודיו, קשר        │
        │  TerrainActor (DEM chunks + LOD + streaming)          │
        │  RunwayActor · Environment (שמש לפי שעה, שמיים, ערפל)  │
        │  HUD (Canvas) · UI (Slate RTL) · Hangar               │
        │  TerrainProviderRegistry ← Plugins/KanafCesium        │
        └───────────────────────────────────────────────────────┘
```

עקרונות:
1. **הפיזיקה מנותקת מהתצוגה.** ‏GroundModel (‏DEM ומסלולים) הוא מקור האמת להתנגשות ולגובה. התצוגה, בין אם רשת DEM ובין אם Google Tiles, היא שכבה שאפשר להחליף.
2. **אפס נכסים בינאריים נדרשים.** העולם, המודל הזמני, הממשק והקלט נבנים ב־C++ בזמן ריצה. לכן הפרויקט נפתח בלי קובצי .uasset/.umap, וכל השינויים נשמרים כטקסט ב־git.
3. **הקטלוג קובע מה מותר.** מטוס זמין לטיסה רק אם הוא `flyable` ויש לו פרופיל. מטוס שסטטוס השירות שלו "הוזמן" לא יכול להיות `flyable`, והבדיקה אוכפת זאת. חימוש זמין רק ברמת `documented` ועם מקור שאינו אתר מאגד.
4. **שקיפות מקורות.** לכל ערך יש סטטוס: אמיתי, הערכה או ערך משחק, וזה מוצג בממשק ובתיעוד.
