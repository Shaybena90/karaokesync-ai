# 🔐 הכספת — טריוויה עם תעלומות

**״כל תשובה מקרבת אותך לפיצוח״**

בכל יום נפתחת כספת חדשה עם תעלומה קצרה. עוברים בשלושה חדרים (ספורט, מוזיקה וידע כללי), עונים על שתי שאלות בכל חדר, אוספים שלושה רמזים ומחברים אותם לקוד בן ארבע ספרות. משחק נמשך 3–5 דקות.

זוהי **גרסה ראשונה (שלב א׳)**: משחק מקומי מלא, בלי שרת ובלי מפתחות API. תוכנית ההמשך נמצאת ב־[ROADMAP.md](ROADMAP.md).

---

## הפעלה

דרוש Node.js 20 ומעלה.

```bash
cd hakasefet
npm install
npm run dev          # פיתוח: http://localhost:5174
```

גרסת הפצה (כולל PWA ו־service worker):

```bash
npm run build
npm run preview      # http://localhost:4174
```

התיקייה `dist/` היא אתר סטטי לכל דבר, וניתן להעלות אותה לכל אחסון סטטי (Netlify, Vercel, GitHub Pages, Cloudflare Pages). הנתיבים יחסיים והניתוב הוא hash (`#/…`), כך שהאתר עובד גם בתת־תיקייה ובלי הגדרות שרת.

### שליחת אתגר לחבר

כפתור ״שיתוף האתגר״ יוצר קישור שמבוסס על הכתובת שבה המשחק פתוח. **כדי שחבר במכשיר אחר יוכל לפתוח את הקישור, המשחק צריך לרוץ בכתובת מארחת נגישה** (למשל אחרי העלאה לאחסון סטטי). קישור מ־`localhost` עובד רק באותו מחשב.

### איך זה עובד

- **כספת יומית**: התאריך נקבע לפי `Asia/Jerusalem`. התעלומה נבחרת ברוטציה מתוך החבילה (`mysteryForDate`). אותה גרסת תוכן + תאריך + תעלומה + רמה → אותן שאלות ואותו סדר תשובות בכל מכשיר (`planQuestions`, PRNG עם seed).
- **ניסיון משחק** הוא אובייקט JSON אחד שנשמר אחרי כל פעולה: מזהי שאלות, סדר האפשרויות, רמה, סדר חדרים, תשובות, רמזים, ניקוד, חותמות זמן ומצב. רענון משחזר אותו בדיוק.
- **טיימר**: לכל שאלה נשמר `deadline`. הזמן נמשך גם כשהלשונית סגורה; בחזרה המצב מיושב, שאלה שפג זמנה מסומנת כטעות, והמשחק מחכה ל״ממשיכים״.
- **חצות**: ניסיון שומר את תאריך הכספת וגרסת התוכן שלו עד הסיום.
- **בלי כפילויות**: ה־reducer מתעלם מפעולות כפולות (לחיצה כפולה, תשובה שנייה). הפרסים נכתבים בטרנזקציית IndexedDB אחת עם מפתח ייחודי (`daily:<תאריך>`, `weekly:<יום ראשון>`) — טרנזקציות חופפות מסודרות בתור גם בין לשוניות, כך שרענון או שתי לשוניות לא מכפילים פרס.
- **PWA**: אחרי טעינה ראשונה שהשלימה שמירה במטמון, כל המשחק עובד בלי רשת. **מדיניות עדכון**: גרסה חדשה לא מוחלפת אוטומטית; מוצעת למשתמש רק כשאין משחק פתוח. חבילות תוכן ישנות נשארות בבנדל, כך שניסיון מסתיים תמיד על גרסת התוכן שבה התחיל.

## הוספת תוכן

אין צורך לשנות את מנוע המשחק. פרטים מלאים ב־[CONTENT.md](CONTENT.md).

- **שאלה**: מוסיפים שורת `q(...)` בקובץ הקטגוריה (`src/content/v1/questions-*.ts`) עם מזהה חדש וקבוע. התשובה הנכונה נכתבת ראשונה; סדר התצוגה מעורבב אוטומטית.
- **תעלומה**: מוסיפים אובייקט ל־`src/content/v1/mysteries.ts` **וגם** fixture ב־`src/content/content.test.ts` שפותר אותה. הבדיקה נכשלת אם הקוד לא נגזר מהרמזים.
- **שינוי שמשנה את הכספות של ימים שכבר עברו** (למשל הוספה/הסרה של שאלות או תעלומות): יוצרים חבילה חדשה (`v2/`), רושמים אותה ב־`src/content/index.ts`, מעדכנים את `CURRENT_VERSION` — ומשאירים את הישנה ברישום כדי שקישורי אתגר ומשחקים פתוחים ימשיכו לעבוד.

## איפוס נתונים

## מגבלות הגרסה המקומית

- **אין תחרות מאומתת.** השאלות, התשובות וקוד הפתרון שמורים במכשיר כדי שאפשר יהיה לשחק בלי רשת. מי שמתעקש יכול לקרוא אותם. לכן מוצגים רק שיאים אישיים, ותוצאה שחבר שלח בהודעה אינה מאומתת. תחרות אמיתית דורשת שרת — ראו [ROADMAP.md](ROADMAP.md).
- ההתקדמות נשמרת רק במכשיר ובדפדפן הזה. ניקוי נתוני האתר או מצב גלישה פרטית מוחקים אותה.
- הקישור לחבר עובד מחוץ למחשב רק כשהמשחק מתארח בכתובת נגישה.
- **אימות עובדות**: בסביבת הפיתוח לא הייתה גישה לאתרי מקורות (הרשת חסמה אותם), ולכן העובדות לא נבדקו מול המקורות ברשת. נבחרו רק עובדות יציבות ומוכרות שנבדקו ידנית; לכל שאלה רשום שם המקור שבו אפשר לאמת אותה, בלי כתובות מומצאות, והשדה `verification` שלה הוא `'offline'`. פרטים ב־[CONTENT.md](CONTENT.md).
