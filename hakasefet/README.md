# 🔐 הכספת — חדרי בריחה ממוחשבים

**״כל רמז מקרב אתכם ליציאה״**

בכל חדר יש 30 דקות לברוח. לוחצים על חפצים כדי לבחון אותם, אוספים פריטים לתיק, משתמשים בהם על חפצים אחרים ופותחים מנעולים: ספרות, אותיות, צבעים, חיצים, מתגים ומחשבים נעולים. אפשר לשחק **לבד**, או **עם 2–4 חברים ברשת** — כל אחד מהטלפון שלו, והכול משותף.

**חדש: 🗝️ חדרי בריחה** — שבעה חדרים עם מכניקות משלהם (טלפון נטוש, כספת מתוזמנת, לולאת זמן, מלון שמשתנה, תחנת חלל, חדר לשני שחקנים בשני מכשירים, ולוח חקירה). נכנסים מהתפריט התחתון ״חדרי בריחה״ או מדף הבית.

## הפעלה

דרוש Node.js 20 ומעלה.

```bash
cd hakasefet
npm install
npm run dev          # פיתוח: http://localhost:5174
npm run build && npm run preview   # גרסת הפצה עם PWA: http://localhost:4174
```

התיקייה `dist/` היא אתר סטטי (Vercel, Netlify וכו׳). הנתיבים יחסיים והניתוב הוא hash (`#/…`).

## חוויות בחדר

לא רק פתקים לקריאה — חלק מהרמזים הם חוויה:
- **📻 כיוון רדיו** (`kind: 'tuner'`): מסובבים חוגה; הרעש הסטטי נחלש ככל שמתקרבים לתדר, ומד קליטה מראה את העוצמה גם בלי צליל. ב״קליטה״ על התדר הנכון נפתח השידור.
- **🔊 הודעות קוליות** (`voice` בפתק): המחשב, הקשר והמפקדה מדברים בעברית בקול הדיבור של המכשיר (Web Speech API), עם אפקט רדיו / טלפון / מחשב שנוצר בקוד. תמיד יש תמליל — למי שמשחק בלי קול, ובמכשיר שאין בו קול עברי.
- **🔦 עדשת UV, 🔍 זכוכית מגדלת, 💡 אלומת אור** (`type: 'reveal'`): מעבירים את העדשה על המסמך, והכתב הנסתר מופיע רק בתוכה. מחזיקים רגע על המקום — והרמז נחשף לכל הצוות. עובד באצבע, בעכבר ובחיצי המקלדת.
- **🎵 מוזיקת רקע לכל חדר** (`src/ui/music.ts`): נוצרת בזמן אמת — מזל״ט, אקורדים, מנגינה דלילה וכלי הקשה לפי האווירה (תקתוק שעון בבונקר, מצעד רחוק במפקדה, צפצופי מורס בצריף). ב־5 הדקות האחרונות הקצב עולה ונכנס דופק לב. אפשר לכבות בפרופיל.

## חדרים מתמונה ריאליסטית
אזור בחדר יכול להיות תמונה אמיתית במקום ציור: `photo` באזור (קובץ ב־`public/rooms/`, ואפשר שכמה אזורים יציגו חלקים שונים מאותה תמונה), ו־`photo: [x, y, w, h]` בכל חפץ, בפיקסלים של התמונה. כפתורים אמיתיים יושבים על החפצים שבתמונה, וחפץ שלא מופיע בה אפשר לצייר עליה (`photoArt`). ״הדרך לירושלים — 1948״ כבר משתמש בתמונה של מפקדת הפלמ״ח. הנחיות ליצירת תמונות לשאר החדרים: [docs/IMAGE_PROMPTS.md](docs/IMAGE_PROMPTS.md).

## תלת־ממד

כל חדר בריחה הוא חדר תלת־ממדי שעומדים בתוכו (WebGL, three.js) — `src/ui/three/escape/`:
- **כל אזור הוא קיר** (עד ארבעה קירות בחדר), והמצלמה מסתובבת ביניהם בתנועה רכה — גם סיבוב של 180°. לחיצה על חפץ מקרבת אליו את המצלמה.
- **כל חפץ הוא מודל תלת־ממדי** (`models.ts`) עם תנועה: מגירות נשלפות, דלתות כספת וארונות נפתחות, מכסים מתרוממים, מסכים נדלקים בהבהוב, לייזרים כבים, נוזלים עולים במבחנות, רשת האוורור נופלת. הציור הדו־ממדי של כל חפץ משמש כ״הדפס״ על הפנים שלו, ברזולוציה לפי האיכות.
- **אווירה:** שישה עיצובים — מעבדה, תחנת חלל, מוזיאון, בונקר בטון (1946), מפקדה מאבן ירושלמית (1948) וצריף עץ (1941). תאורת חירום עד שהחשמל חוזר (`darkUntil` בהגדרת החדר), נורות תלויות בחדרים ההיסטוריים, זרקורים במוזיאון, פסי ניאון, אבק באור, צללים רכים וזוהר (bloom), ורגע בריחה קולנועי בסוף.
- **מראה קולנועי:** הצללה סביבתית (GTAO — צללים רכים בפינות ובמגע בין חפצים) באולטרה, ויגנט וגרעין פילם עדין, ונורות שמהבהבות בחדרים ההיסטוריים.
- **איכות גרפיקה** (פרופיל → איכות גרפיקה): אולטרה 4K (רזולוציה מקורית עד ×3, צללים 2048, החלקת קצוות, הצללה סביבתית), גבוהה, רגילה, ודו־ממד. כל התוכן נוצר בקוד ומוצג ברזולוציה המלאה של המסך — אין קובצי תמונה.
- **ביצועים:** אם המכשיר איטי, הרזולוציה יורדת אוטומטית. כשאין תנועה המסך מתעדכן ב־30 פריימים בשנייה, והציור נעצר כשהלשונית מוסתרת. בלי WebGL עוברים אוטומטית לדו־ממד.
- **נגישות:** מעל התמונה יש שכבת כפתורים אמיתיים בדיוק במקום כל חפץ — עובדים עם מגע, מקלדת וקורא מסך.

## הפעלת משחק עם חברים (Supabase)

משחק לבד עובד מיד. משחק ברשת משתמש ב־**Supabase Realtime** — רק בערוצי שידור ונוכחות, **בלי טבלאות ובלי קוד שרת**. צריך שני ערכים ציבוריים:

| משתנה | מאיפה |
|---|---|
| `VITE_SUPABASE_URL` | Supabase → Project Settings → API → Project URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase → Project Settings → API → `anon` `public` key |

אפשר להשתמש באותו פרויקט Supabase של אפליקציית הקריוקי. ב־Vercel: פרויקט ההכספת → **Settings → Environment Variables** → מוסיפים את שני המשתנים → **Deployments → Redeploy**. מקומית: קובץ `hakasefet/.env.local`.

- המפתח `anon` ציבורי מטבעו ובטוח בדפדפן. **לעולם לא** לשים כאן `service_role` — `vite.config.ts` עוצר את הבנייה אם משתנה `VITE_` נראה סודי.
- ב־Supabase, תחת Realtime Settings, צריך שהגישה לערוצים ציבוריים תהיה מותרת (ברירת המחדל).
- **בדיקה בלי Supabase:** בקונסול של הדפדפן `localStorage.setItem('hakasefet:net','local')` ורענון — שתי לשוניות באותו דפדפן ישחקו יחד (כך רצות הבדיקות האוטומטיות).

### איך הסנכרון עובד
- **חדר משותף לפי קוד** (5 תווים), עם קישור הזמנה `#/coop/CODE`. עד 4 שחקנים.
- **המארח קובע:** השחקן הוותיק ביותר שמחובר הוא המארח. שאר השחקנים שולחים אליו פעולות, הוא מפעיל אותן במנוע ומשדר את המצב לכולם.
- **בלי כפילויות:** לכל פעולה מזהה ייחודי, והמנוע מפעיל כל מזהה פעם אחת — כך שאפשר לשלוח שוב אחרי ניתוק בלי חשש.
- **ניתוקים:** אם המארח יוצא, השחקן הבא הופך למארח וממשיך מהמצב האחרון. מי שמרענן חוזר לחדר ומקבל את המצב מהאחרים (או מהגיבוי במכשיר).
- **מי איפה:** כל אחד רואה אילו חברים נמצאים בכל אזור בחדר, והודעה קופצת על כל התקדמות (״🦊 דנה: המגירה נפתחה!״).

**תוכן ומנוע בנפרד:** החדרים הם נתונים (`src/escape/rooms/collection/*.ts`, `src/pair/logic.ts`) עם `CONTENT_VERSION`. `src/escape/validate.ts` בודק כל חדר: מזהים כפולים, הפניות לדברים שלא קיימים, שלבים שהפתרון לא מגיע אליהם, תלות מעגלית, ופתרונות שלא מתאימים למנעול. **פתרונות למפתחים:** [docs/ESCAPE_SOLUTIONS.md](docs/ESCAPE_SOLUTIONS.md) — נוצר מהתוכן ונבדק בבדיקות (לא מוצג באפליקציה).

### שרת החדר הזוגי

החדר ״שני צדדים של הדלת״ צריך שירות קטן בזמן אמת (WebSocket). שאר החדרים עובדים בלעדיו.

```bash
npm run pair-server          # מאזין ב־8787 (או PAIR_PORT)
```

- הדפדפן מתחבר ל־`VITE_PAIR_SERVER_URL` (למשל `wss://pair.example.com`), ואם הוא ריק — ל־`ws://<אותו שרת>:8787`.
- באתר HTTPS (כמו Vercel) צריך כתובת `wss://` — מארחים את `server/pair-server.ts` בשירות שמריץ Node (Render, Fly.io, Railway וכו׳) ומגדירים את הכתובת ב־`VITE_PAIR_SERVER_URL`, ואז Redeploy.
- השרת שומר את החדרים בזיכרון: חדר נסגר אחרי 3 שעות, או אחרי 30 דקות שאף אחד לא מחובר. הפעלה מחדש של השרת מוחקת חדרים פעילים.
- אבטחה: השרת מחליט על כל תשובה, שולח לכל שחקן רק את המידע של התפקיד שלו, מקבל כל פעולה פעם אחת (מזהה ייחודי), ומחזיר שגיאות ברורות לקוד שגוי / חדר מלא / חדר שפג תוקפו.

### רמות קושי
| | 🟢 קל | 🟡 בינוני | 🔴 קשה |
|---|---|---|---|
| שעון | 60 דקות | 50 דקות | 40 דקות |
| רמזים | בלי הגבלה, +30 שניות | בלי הגבלה, +1 דקה | עד 3, +2 דקות |
| רמזים שבחדר | ניסוח ברור יותר | רגיל | ניסוח מעורפל יותר |

את הרמה בוחרים לפני שמתחילים; במשחק משותף — המארח. כל פתק יכול להגדיר `easy` ו־`hard` (ניסוח חלופי). הבדיקות מריצות את מסלול הפתרון של **כל חדר בכל רמה**.

**ניקוד:** הזמן כולל את קנס הרמזים. ⭐⭐⭐ עד 60% מזמן הרמה, ⭐⭐ עד 85%, ⭐ בזמן; אחרי שהזמן נגמר אפשר להמשיך ולברוח בלי כוכבים.
**פרסים:** בריחה ראשונה מכל חדר **בכל רמה** — קל 80 XP + 20 מטבעות, בינוני 120 + 30, קשה 180 + 45. בריחה ראשונה בכל יום — עוד 50 XP + 20 מטבעות. שיאים נשמרים לכל רמה בנפרד.

```
├─ storage/                IndexedDB (schema v3 עם מיגרציות): פרופיל, בריחות, פרסים
├─ ui/escape/              ציור הסצנות (SVG), מנעולים, מסך המשחק ומסך הבריחה
├─ ui/three/               הכספת התלת־ממדית (three.js)
└─ pages/                  בית, חדרים, לבד, חברים, החדר שלי, פרופיל
```

### הוספת חדר בריחה
יוצרים קובץ ב־`src/escape/rooms/`, ומוסיפים אותו לרשימה ב־`rooms/index.ts`. אין צורך לשנות את המנוע. כל חפץ מוגדר כרשימת אינטראקציות (הערה, לקיחה, מנעול, צריך פריט); הראשונה שהתנאים שלה מתקיימים היא הפעילה. **חובה** למלא `walkthrough` — הבדיקות מריצות אותו ומוודאות שהחדר פתיר, שכל רמז רלוונטי בדרך ושלכל חפץ יש תגובה. ציור לחפץ חדש מוסיפים ב־`ui/escape/sceneArt.tsx`.

## בדיקות

```bash
npm test             # יחידה: מנוע + 3 חדרים, סנכרון רב־משתתפים, אחסון ופרסים, תאריכים
npm run typecheck && npm run lint && npm run build
npm run e2e          # Playwright (מפעיל גם את שרת החדר הזוגי): כל 6 חדרי הבריחה מתחילתם ועד הסוף, החדר הזוגי בשני דפדפנים, בריחה מלאה לבד, משחק משותף בשתי לשוניות, חדר תלת־ממדי באיכות גבוהה, טלפון 360px, בלי רשת
```

- **סנכרון:** `net/session.test.ts` מדמה ״שרת״ בזיכרון: הצטרפות, פעולות של כל שחקן, יציאת מארח, רענון עם גיבוי ישן, הודעות שאבדו ונשלחו שוב, תקרה של 4 שחקנים.
- **e2e שיתופי:** שני שחקנים בשתי לשוניות — יצירת חדר, הצטרפות בקישור, התקדמות משותפת, המארח עוזב, הצוות בורח.
- **תלת־ממד בבדיקות:** דפדפן הבדיקות רץ בלי כרטיס מסך, לכן בדיקות המסלול הארוכות רצות בתצוגה הדו־ממדית (אותו מנוע משחק), ובדיקה נפרדת מוודאת שהחדר התלת־ממדי נטען באיכות גבוהה ושאפשר ללחוץ על החפצים בו.
- **חדרי הבריחה:** `validate.test.ts` (תקינות תוכן + בדיקות שמראות שהבודק תופס שגיאות), `collection.test.ts` (ניקוד, רמזים, שילוב, שעון ואימון, לולאה ושחזור), `pair/logic.test.ts` (תפקידים, אימות, כפילויות, מידע לפי תפקיד). `e2e/escape.spec.ts` עובר כל חדר: תשובה שגויה, רמז, רענון באמצע, פתרון מלא, ניקוד והסבר. `e2e/pair.spec.ts`: שני דפדפנים, הזמנה, ״מוכן״, תשובה שגויה, ניתוק וחזרה, חדר מלא, קוד שגוי ויציאה משותפת.
- **לא נבדק אוטומטית:** חיבור אמיתי ל־Supabase (אין גישה אליו מסביבת הבדיקות). אותו קוד סנכרון רץ בשני המקרים; רק שכבת התקשורת שונה.
